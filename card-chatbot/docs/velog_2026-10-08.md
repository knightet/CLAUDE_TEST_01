## 들어가며

가지고 있는 카드의 상품설명서를 근거로 "어디서 얼마 쓰면 어떤 카드가 이득인지" 알려주는 챗봇을 만들고 있다.
[지난 글](#)에서는 "계산은 코드, 설명만 AI"로 구조를 바꾸고 공격 테스트로 오류를 뽑았다.
이번 글은 **중간 점검에서 받은 피드백**을 어떻게 반영했는지, 그리고 **코드를 동결하고 최종 측정**한 과정과 그 뒤에 추가로 고친 것들을 정리한다.

## 중간 점검에서 받은 피드백

> - **설명서**: 최신 설명서를 찾아보고, 안 되면 지금 것을 그대로 쓰는 방향으로
> - **공격 테스트**: 1차 → 2차에서 남은 오류 처리
> - **질문 해석**: 질문 칸(가맹점 / 금액 / 수량 / 시간)을 미리 마련하고 코드가 검사하게. 해석이 실행마다 달라지지 않게 하는 게 더 좋다
> - **혜택 중복**: 중복이 안 되는 쪽으로 먼저 계산하기. 부풀려서 말하는 것보다 적게 말하는 게 안전하다

중간 점검 때 상태는 이랬다.

| 항목 | 상태 |
|---|---|
| 공격 테스트 2차 | 82/92 (10건 남음) |
| 방식 비교 100문항 (고친 후) | 1위 금액 96/100. 틀린 4건은 **모두 질문 해석 문제** |
| 설명서 | 헤이영 2022년판, K-패스 2024년판, Mr.Life는 홈페이지 자료 |
| 카드 데이터 | 9장 모두 "초안 - 사람 검수 필요" |

## 1. 질문 해석: 칸을 정해 두고 코드가 채운다

### 문제

그때는 GPT가 질문을 JSON으로 해석하고, 계산만 코드가 했다. 그런데 **같은 질문인데 실행마다 해석이 달라졌다.**

- "체크카드 중에 스벅 15000원": 17문항으로 돌릴 때는 맞았는데, 100문항으로 돌릴 때는 틀림
- "SKT 통신요금 5만원": 하루 전에는 결제 질문으로 읽었는데, 다음 날은 "실적에 포함되냐"는 질문으로 읽음

계산이 아무리 정확해도 해석이 흔들리면 답이 흔들린다.

### 바꾼 것

- 질문 칸을 미리 정했다: **가맹점 · 금액 · 수량 · 시간 · 요일 · 카드 · 결제수단**, 이후 **결제 방식(인앱결제 등) · 연료(LPG 등) · 비교할 카드 · 제외할 카드**까지
- 칸은 전부 **코드 규칙**이 채운다. 질문 종류(결제 혜택 / 실적 포함 여부 / 카드 정보)도 코드가 정한다
- GPT가 하는 일은 하나만 남겼다: 코드가 가맹점을 못 찾았을 때 **가맹점 이름 후보를 제안**. 그 이름이 질문에 **글자 그대로 있을 때만** 쓴다
- 답변 문장도 코드가 계산 결과로 만든다. GPT가 카드별 사실을 요약하다 다른 카드 조건을 섞은 적이 있어서다 (GPT 설명 기능은 꺼 두었고, 켜도 계산에 없는 숫자·카드가 섞이면 버린다)

화면에는 코드가 읽은 칸을 그대로 보여준다.

```
질문: 오후 2시 백화점 스벅 15000원 KB Pay로
이렇게 이해했어요: 가맹점 스타벅스 · 금액 15,000원 · 시간 오후 2시 · 장소 백화점 입점 매장 · 결제수단 KB Pay
```

### 결과

- 같은 질문은 항상 같은 해석
- 방식 비교 100문항 (고친 후) 1위 금액: 96/100 → 100/100
- 이 100문항은 보면서 고친 문항이라, 일반화는 아래 홀드아웃으로 따로 확인했다

## 2. 공격 테스트: 2차 오류를 막고, 3차를 새로 만들었다

2차에서 남은 10건은 대부분 "칸이 없어서" 생긴 오류였다.

| 질문 | 문제 | 고친 방법 |
|---|---|---|
| 오후 2시 스벅에서 만원짜리 커피 3잔 | 10,000원으로 계산 | **수량 칸** 추가 → 30,000원 |
| 토요일 LPG 충전소 3만원 | "충전"을 선불 충전으로 읽음 | 연료 칸 추가, "충전소"는 충전 아님 |
| 넷플릭스 13500원 인앱결제 | 인앱결제 제외 조건 무시 | 결제 방식 칸 추가 |
| 노리랑 헤이영 중에 스벅 | 9장 전체 비교 | 비교할 카드 칸 추가 |
| K패스 말고 다른 카드로 | K-패스도 포함 | 제외할 카드 칸 추가 |

결과는 82/92 → 92/92.

그런데 **고친 문항만 다시 돌리면 늘 통과한다.** 그래서 처음 보는 표현으로 3차 30문항을 새로 만들었다. 첫 실행은 **26/30**이었다.

- "오후 2시 스벅 만 오천": '원' 없는 한글 금액
- "밤 열한시 택시 9000원": 한글 숫자 시각 → 심야 할인 누락
- "23:30 택시 9000원": 시:분 형식
- "KB페이로 편의점 12000원": 'KB페이' 표기

이 4건을 고쳐 전체 124/124가 됐다. 그래도 "처음 보는 표현에서는 26/30"이라는 숫자가 이 구조의 한계를 그대로 보여준다고 생각한다.

## 3. 혜택 중복: 적게 계산하는 쪽으로

카드 한 장에서 같은 결제에 혜택 여러 개가 걸리면 **가장 큰 혜택 하나만** 적용한다.
나머지는 버리지 않고, 계산 근거에 이렇게 표시한다.

```
✗ 중복: 같은 결제에 더 큰 혜택이 적용되어 제외
```

설명서에 **함께 받을 수 있다고 분명히 적힌 경우만** 더한다. 혜택 65개 중 2개뿐이다.

- K-패스: 생활서비스 5% + **KB Pay 추가 5%** (편의점 12,000원 KB Pay → 600 + 600 = 1,200원)
- NH 올바른FLEX: **NH pay 건당 1천원** ("타 상품서비스와 중복 적용 가능")

설명서에 중복 여부가 불명확했던 Youth Club 프로모션과 기본 팩은 사람이 직접 확인했다.

## 4. 설명서: 최신판 대신 사람 검수

헤이영·K-패스 최신판과 Mr.Life 공식 설명서는 구하지 못해서, 피드백대로 **지금 설명서를 그대로 쓰기로** 했다.
대신 카드 데이터를 사람이 원본 PDF와 한 줄씩 대조했다. 검수 지적 7건을 다시 원본과 대조해 맞는 것만 반영했는데, 실제 계산 오류가 하나 나왔다.

- **노리 통신요금**: 설명서는 "5% 환급, 건당 5만원 이상이면 2,500원 정액"인데, 데이터에는 5만원 이상만 있어 **5만원 미만 통신요금이 0원으로 계산**되고 있었다 → 수정하고 계산 평가 2문항 추가 (131 → 133문항)

9장 모두 "사람 검수 완료 (현재 보유 설명서 기준)"로 바꿨고, 오래된 설명서는 한계로 적어 두었다.

## 5. 최종 측정: 코드를 멈추고 한 번만

- **코드 동결**: `37b55cd` (10-06 16:08). 이후 해석 규칙·엔진·답변·데이터·화면을 고치지 않음
- **홀드아웃 잠금**: `4b172c8` (16:10). 개발 중 한 번도 안 쓴 가맹점 15문항(CGV, 에버랜드, 올리브영, 요기요, 고속버스 등)과 정답을 **측정 전에 커밋**
- **측정**: 16:12에 한 번. 결과를 보고 고치지 않음

| 채점 항목 | GPT 빈손 | 고치기 전 | 고친 후 (개발 100) | 고친 후 (홀드아웃 15) |
|---|---|---|---|---|
| 검색 적중 (맞는 조항) | 해당 없음 | 해당 없음 | 미측정 | 15/15 |
| 1위 금액 (개발 · 홀드아웃) | 11/100 · 1/15 | 42/100 · 5/15 | 100/100 | 15/15 |
| 1위 카드 (동률 제외) | 41/72 · 0/14 | 41/72 · 5/14 | 72/72 | 14/14 |

- 채점: 프로그램 (정해 둔 정답과 비교). 정답은 사람이 검수한 카드 데이터로 AI(Claude)가 계산했고, 홀드아웃 정답의 사람 재확인은 아직 안 했다
- 답변 모델: GPT 빈손·고치기 전은 gpt-4o-mini가 답 전체를 냄. 고친 후는 코드가 계산하고 gpt-4o-mini는 가맹점 이름 후보만

GPT 빈손의 실제 오답 하나:

```
질문: 오후 7시 CGV에서 영화 18000원
GPT 빈손: 굿데이 18,000원 / Mr.Life 18,000원 / K-패스 18,000원  ← 결제 금액 전체를 "할인"이라고 함
정답:     노리 체크 6,300원 (18,000원 × 35%, 상품설명서 1p) / NH 올바른FLEX 5,000원 / K-패스 900원
```

## 6. 측정 이후에 고친 것들 (점수에는 넣지 않음)

동결 후에는 **사람들이 많이 물을 질문**으로 새 테스트를 만들었다. 카드 검색 통계에서 많이 찾는 영역(카페·편의점·온라인쇼핑·OTT)에 배달앱·대중교통·통신비·해외결제를 더하고, 실제 말투(줄임말, 금액 없이 묻기, 후속 질문)로 73문항을 만들었다.

동결 코드로 첫 실행 결과는 **61/73**. 틀린 12건은 모두 계산이 아니라 **질문 해석** 단계였다.

| 질문 | 문제 | 고친 뒤 |
|---|---|---|
| 일본에서 1만엔 | 10,000원으로 계산 (실제 약 9만원) | 원화 금액을 되물음 |
| 지에스 3천원, 넷플 17000 | 줄임말을 몰라 가맹점을 되물음 | GS25, 넷플릭스로 계산 |
| 빽다방, 디즈니플러스, 통신비, 교통비 | 사전에 없는 말 | 사전 보강 |
| 영화 15000원 | 가맹점을 모름 | "CGV에서는 노리 5,250원 · 롯데시네마에서는 NH 4,500원" |
| 배민 2만원 → 노리로는? | "혜택 받을 카드가 없어요" | "노리는 혜택이 없어요. 보유 카드 중에서는 NH 2,000원" |

직접 써 보다가 찾은 것도 있다.

- **사용 기록 버그**: 스타벅스 결제를 "썼어요"로 기록하면, 질문에 "토요일"을 적어도 "일 1회 모두 사용함"으로 NH가 빠졌다. 하루 횟수를 **질문한 요일이 아니라 오늘 기록**으로 판정하고 있었다 → 다른 요일이면 오늘 횟수는 세지 않도록 수정. 기록 때문에 빠진 카드는 "기록이 없으면 5,000원"처럼 이유도 보여주게 했다
- **이어받기 버그**: "이마트24 12000원" 다음에 "일본에서 1만엔"을 물으면 앞 질문에 이어 붙여 "이마트24 12,000원 해외"로 계산했다 → 외화 질문은 새 질문으로
- **없는 카드**: "현대카드 혜택 알려줘"에 보유 카드 목록을 보여줬다 → "등록된 카드 자료에 없다"고 답하도록. 처음엔 "연회비 제일 **싼** 카드"의 '싼'을 카드 이름으로 읽어서, 'ㄴ' 받침으로 끝나는 꾸미는 말은 빼도록 고쳤다

지금은 많이 물을 질문 85/85, 공격 테스트 124/124, 성질 검사 오류 0건이다.
수정한 코드로 홀드아웃 15문항을 다시 돌려도 답이 측정 기록과 15/15 같았다. 다만 동결 후 수정이라 **발표 점수는 동결 기준 그대로** 둔다.

## 배운 점

- **해석이 흔들리면 계산이 정확해도 소용없다.** 칸을 정해 두고 코드가 채우니 같은 질문에 같은 답이 나왔다
- **고친 문항만 돌리면 점수는 늘 높다.** 처음 보는 문항을 돌릴 때마다 26/30, 61/73처럼 새 오류가 나왔다. 그래서 홀드아웃은 측정 전에 커밋해 잠갔다
- **적게 말하는 쪽이 안전하다.** 중복이 불명확하면 큰 혜택 하나만, 외화나 모르는 카드는 추측하지 않고 되묻는다

## 다음에 할 것

- 실제 사용자 5~10명에게 질문을 받아 2차 홀드아웃 (정답은 사람이 검수)
- 헤이영·K-패스 최신 설명서, Mr.Life 공식 설명서로 교체
- 한 달 소비 패턴("편의점 월 5만, 커피 8만")을 넣으면 카드 조합과 한 달 총 혜택 계산
