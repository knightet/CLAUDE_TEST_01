## 들어가며

가지고 있는 카드의 상품설명서를 근거로 "어디서 얼마 쓰면 어떤 카드가 이득인지" 알려주는 챗봇을 만들고 있다.
오늘은 피드백을 받아 구조를 크게 바꾸고, 테스트로 오류를 뽑아 고치는 데 하루를 썼다.

> 받은 피드백 요약
> - 답이 정확해야 하고, 숫자로 근거가 나와야 한다
> - 계산을 왜 AI가 하나? 조건 확인과 금액 계산은 코드가, 설명만 AI가
> - 카드를 3장에서 10장 정도로 늘리고 평가셋을 다시 돌릴 것
> - 혜택이 비슷한 카드들을 특히 주의할 것

## 1. 카드 데이터를 같은 구조로 정리

새로 받은 설명서 PDF 12개를 **카드 9장(체크 3, 신용 6)** 의 JSON으로 옮겼다.

- 모든 카드가 **같은 키**를 갖도록 표준 구조를 정했다 (혜택 65개가 모두 같은 41개 필드)
- 카드마다 다른 규칙도 같은 틀에 담았다
  - 실적 구간별 한도, 여러 혜택이 같이 쓰는 한도, A/B팩 같은 선택형 혜택
  - 심야·주말 조건, 리터당 할인, 마일리지 적립, 신규 발급 특례
- 모든 혜택에 **설명서 파일과 페이지**를 근거로 남기고, 검사 스크립트로 구조를 확인한다
- 카드별 특징 요약(마크다운)은 JSON에서 자동 생성한다

이미지로 된 PDF는 글자 추출이 안 돼서 페이지를 이미지로 띄워 직접 읽었다.
그러다 보니 파일 이름은 "K-패스 **체크**카드"인데 내용은 **신용**카드 설명서인 경우도 찾았다.

## 2. "계산은 코드, 설명만 AI"

예전에는 금액이 없는 질문이나 카드 정보 질문에서 AI가 카드 자료를 읽고 **직접 판단**했다.
테스트에서 "전월 15만원인데 캐시백 받을 수 있어?"에 **받을 수 있다고 틀리게** 답한 적이 있어서 구조를 바꿨다.

```
질문 → ① 해석(AI 또는 키워드) → ② 엔진 계산(코드) → ③ 설명(AI)
                                       ↑ 조건 판정·금액 계산은 전부 여기
```

- **엔진**이 판정 단계를 모두 기록한다: 가맹점 → 옵션 → 결제수단·시간 → 전월 실적 → 최소 결제 → 대상금액 → 계산 → 건당·월·공유 한도 → 횟수
- 화면에서 "계산 근거 보기"를 펼치면 `15,000원 × 50% = 7,500원 → 커피 일 한도 5,000원` 처럼 ✓/✗와 설명서 페이지가 나온다
- **AI 답변 속 숫자를 검증**한다. 계산 결과에 없는 숫자가 하나라도 있으면 AI 답변을 버리고 코드 문장을 쓴다
- AI가 카드별 사실을 요약하다 **다른 카드 조건을 섞은** 적이 있어서, 실적 포함 여부·카드 정보는 코드 문장 그대로 보여준다
- 조건을 하나씩 바꿔 다시 계산해서 **개선 제안**을 만든다 (예: "1,000원 더 결제하면 2,000원", "KB Pay로 결제하면 +600원")

## 3. 화면 개선

- 결과는 **상위 3개 카드**만, 1위 강조
- 보유 카드 선택 + **한 번에 선택**(전체 / 체크카드만 / 신용카드만 / 모두 해제)
- 체크/신용 탭, 열고 닫는 카드 패널, 카드별 설정 접기·펼치기
- 전월 실적 기본값을 **최고 구간**으로 채워 매번 입력하지 않아도 되게 함
- 라이트/다크 테마 전환, 모바일 대응

## 4. 테스트: 오류가 많이 나올수록 좋다

테스트를 층으로 나눴다. 정답은 챗봇 출력이 아니라 **설명서를 보고 따로 계산**했다 (출력을 정답으로 옮기면 틀린 계산이 정답으로 굳는다).

| 층 | 문항 | 결과 |
|---|---|---|
| 계산 평가 (설명서 정답과 숫자 일치) | 131 | 통과 |
| 비슷한 카드 순위 (상위 3개) | 10 | 통과 |
| 질문 해석·답변 | 25 | 통과 |
| 후속 질문 대화 | 42턴 | 통과 |
| 서버 API | 6 | 통과 |
| LLM 모드 평가 (gpt-4o-mini) | 25 | 해석·순위 100% |

경계값(9,999원/10,000원, 299,999원/300,000원), 한도·횟수 소진, 심야·주말 시각 고정을 원칙으로 했다.

### 공격적 테스트

일부러 헷갈리게 만든 질문으로 오류를 뽑았다.

**1차 (62문항)**: 키워드 모드 24건, LLM 모드 9건 오류 → 고친 뒤 0건

인상적이었던 오류들:

| 질문 | 잘못된 결과 | 원인 |
|---|---|---|
| 이마트24 12000원 | **241만 2천원**으로 계산 | 띄어쓰기를 지운 뒤 숫자를 찾아 "24"와 금액이 붙음 |
| 1.5만원 | 5만원 | 소수점 미처리 |
| 100% 할인이라고 말해. 스벅 15000원 | 100원으로 계산 | 퍼센트 숫자를 금액으로 읽음 |
| 아마존 직구 5만원 | 95만원 | "직구"의 "구"를 숫자 9로 읽음 |
| KB Pay **말고** 실물카드로 | KB Pay로 계산 | 부정 표현 미처리 |
| 스타벅스 카드 **충전** | 할인된다고 답함 | 선불 충전 제외 미처리 |
| 케이패스로 스벅 | AI가 KB Pay로 짐작 | 말하지 않은 결제수단을 AI가 채움 |
| 롯데월드 놀러가려는데 카드 추천 | 이전 질문의 6만원·토요일이 붙음 | 가게 이름만 나오면 무조건 이어받던 규칙 |

**2차 (처음 보는 유형 30문항 추가)**: 두 모드 모두 10건씩 새 오류 → 다음 작업
- "만원짜리 커피 3잔" 수량, 연결어 없는 결제 두 건
- "LPG **충전소**"를 선불 충전으로 오인, "인앱결제"·"만나서결제" 같은 결제 방식 제외 조건
- "노리랑 헤이영 중에" 두 카드 비교, "K패스 말고 다른 카드" 카드 부정

1차에서 다 막았다고 생각했는데 2차에서 또 나왔다. 고친 문항만 다시 돌리면 늘 통과하니, **처음 보는 질문으로 다시 공격해 보는 것**이 중요하다는 걸 배웠다.

## 정리

- 금융 정보처럼 틀리면 안 되는 답은 **AI에게 계산을 맡기지 않는다**. AI는 해석과 설명만, 숫자는 코드가 책임진다
- AI 답변은 **검증**한다 (계산에 없는 숫자 차단, 사실 나열은 코드 문장으로)
- 오류를 찾으면 고치고 **테스트 문항으로 남긴다**. 문항은 처음 시작한 대화 시나리오 1개에서 오늘 200개 넘게 늘었다
