# 카드 혜택 챗봇 중간 점검 (2026-10-02)

## 1. 한 줄 상태

**주제:** 보유 카드 설명서를 근거로 "어디서 얼마 쓰면 어떤 카드가 얼마나 이득인지"를 숫자와 근거 페이지로 답하는 챗봇
**상태:** 🟢 **순조로움.** 핵심 구조(계산은 코드, 설명만 AI)와 카드 9장, 테스트 체계를 완성했습니다. 2차 공격 테스트에서 나온 오류 10건은 원인까지 파악했고 수정만 남았습니다.

### 정답과 근거 위치

- 정답은 **챗봇 출력을 옮기지 않고 설명서를 보고 따로 계산**했습니다. 출력을 정답으로 쓰면 틀린 계산이 정답으로 굳기 때문입니다.
- 문항마다 근거를 적었습니다. 예시:

## 5. 숫자 표

같은 17문항(정답 순위가 있는 질문), 같은 조건(카드 9장, 같은 전월 실적), 같은 모델(gpt-4o-mini, temperature 0)로 비교했습니다.

| 방식 | 설명 | 1위 금액 정답 | 상위 3개 금액 모두 정답 | 1위 카드 정답 |
|---|---|---|---|---|
| **A. GPT 빈손** | 카드 자료 없이 카드 이름과 전월 실적만 주고 질문 | 4/17 (**24%**) | 0/17 (0%) | 1/6 (17%) |
| **B. 고치기 전** | 카드 설명서 요약 전체를 주고 GPT가 조건 판단과 계산까지 함 | 7/17 (**41%**) | 2/17 (12%) | 3/6 (50%) |
| **C. 고친 후** | GPT는 질문 해석만, 조건 판단과 계산은 엔진 | 16/17 (**94%**) | 16/17 (94%) | 5/6 (83%) |

- C에서 틀린 1건은 계산이 아니라 **질문 해석** 오류입니다 (7번 사례 4).
- **참고 1:** B는 예전 코드를 지웠기 때문에 지금 카드 9장 자료로 예전 방식을 다시 재현한 것입니다.
- **참고 2:** 이 프로젝트의 "검색"은 벡터 검색이 아닙니다. 질문을 해석해서 가맹점·카드로 혜택을 찾습니다. 그래서 B는 "자료를 프롬프트에 넣고 GPT가 판단", C는 "자료로 코드가 계산"을 비교한 것입니다.
- **참고 3:** 문항이 17개로 적습니다. 그래서 비율보다는 차이의 방향을 봐야 합니다.

## 6. 효과 있었던 변경

| 변경 | 효과 |
|---|---|
| **조건 판정과 계산을 코드(엔진)로 옮김** | 1위 금액 정답률 41% → 94%. 전월 실적 미달인데 "받을 수 있다"고 답하던 오류가 사라짐 |
| **AI 답변 숫자 검증** | 계산에 없는 숫자가 한 개라도 있으면 코드 문장으로 대체. 잘못된 금액이 답변에 나갈 수 없음 |
| **사실 나열은 코드 문장으로** | AI가 카드 A의 조건을 카드 B에 붙이던 오류 제거 (실적 포함 여부, 카드 정보, 혜택 0원 안내) |
| **카드 데이터 표준 구조** | 실적 구간별 한도, 공유 한도, 선택형 혜택, 리터당 할인, 마일리지까지 같은 틀로 계산. 카드 추가 시 코드 수정 없음 |
| **계산 단계 기록 (계산 근거 보기)** | 가맹점 → 결제수단 → 전월 실적 → 최소 결제 → 한도 → 횟수를 ✓/✗와 페이지로 표시. 틀린 단계를 바로 찾을 수 있음 |
| **제외 조건 정확 일치** | "해외 스타벅스"가 스타벅스 혜택을 통째로 막던 부분 문자열 매칭 버그 수정 |
| **한글 금액 해석 (`korean_number`)** | "만오천원", "1.5만원", "직구"의 '구'를 9로 읽던 문제 등. 공격 1차 키워드 모드 61% → 100%의 주요 원인 |
| **후속 질문 규칙** | 가게 이름만 말한 질문은 짧거나 이어받는 표현이 있을 때만 이전 질문을 이어받음 ("롯데월드 놀러가려는데 카드 추천" 오류 해결) |
| **정답을 설명서에서 따로 계산** | 테스트가 버그를 정답으로 굳히는 일을 막음. 문항 작성 중 계산 오류를 1건 더 발견 |

## 7. 실패 사례

**사례 1. 설명서를 줘도 GPT가 1위를 놓침 (B 방식)**
- **질문:** 스벅 만오천원
- **가져온 조각:** NH 올바른FLEX "스타벅스 50% 청구할인, 전월 30만원 이상, 일 1회/월 2회" (nh_allbareun_flex.pdf 2p)
- **답:** 헤이영 1,000원, 노리 3,000원, 굿데이 0원 (정답: NH 5,000원, 노리 3,000원, 굿데이 1,500원)
- **틀린 이유 추정:** 카드 9장의 자료(약 5만 자)를 한 번에 받으면 GPT가 모든 카드를 빠짐없이 비교하지 못합니다. 순서도 금액 순으로 정렬되지 않았습니다. 코드는 9장 × 65개 혜택을 전부 계산하므로 이런 누락이 없습니다.

**사례 2. 제외 조건을 무시함 (B 방식)**
- **질문:** 오후 2시 백화점 스벅 15000원
- **가져온 조각:** 노리 스타벅스 할인 "제외: 백화점·대형마트 등 입점 일부 매장" (kb_nori_check.pdf 1p)
- **답:** 노리 3,000원 할인 (정답: 노리 0원, 1위 K-패스 750원)
- **틀린 이유 추정:** 혜택 표의 할인율은 반영했지만 아래쪽 제외 문구를 같이 적용하지 못했습니다. 엔진은 결제 장소를 제외 목록과 단계별로 대조합니다.

**사례 3. 자료가 없으면 지어냄 (A 방식)**
- **질문:** CU 25000원 NH페이로
- **가져온 조각:** 없음 (빈손)
